# UI/UX 配套后端验收

日期：2026-10-05。依据 [设计草案](../design/Bilive_DESIGN_draft.md) 第 10、15–17、19–21 节，补齐 [第一版前端验收](uiux-first-version-acceptance.md) 当时列出的后端缺口。按用户要求，截图样式收尾留待后续。

## 已实现

- 设置：发布默认、清理策略、路径及高级参数可在网页编辑；六分区草稿统一校验、一次原子保存。保存保留既有 TOML 注释、无关字段和旧 `slice.*` 配置，标准字段重载后优先。自动分析、字幕默认样式、发布默认和清理策略立即生效；运行参数、路径和上传消费者参数提示重启对应服务。环境变量仍有优先级，并返回覆盖提示。凭据与服务身份参数不进入编辑接口。
- 发布信息：全局 → 主播 → 单片段覆盖标题模板、简介、标签、分区。标题模板支持 `{title}`、`{streamer}`、`{room}`、`{date}`。新人工/分析片段复制当前默认，后续修改默认不追写旧片段。修改单片段发布信息保留有效成片和当前完整预览记录，仍检查版本、任务互斥和批准锁定。
- 封面：生成成片时用真实 FFmpeg 从成片生成 960×540 默认封面，在成片模式展示；上传消费者将封面及单片段分区传入既有投稿协议。封面 URL 和远端视频标识持久化，投稿重试复用已上传内容。
- 完整预览：播放器的实际 `played` 区间按当前媒体版本合并保存，覆盖整片后显示完整预览；重新生成使旧记录失效。记录只辅助确认，人工批准不以此作为强制门槛。
- 主播历史：最近 5 条成功发布记录读取真实上传库，提供 B 站回链。
- 生命周期：未处理源录播默认 5 天；所有保留片段成功发布后，以最后成功时间起算 24 小时。部分发布的场次不会被单个片段提前缩短期限。发布日期写入独立 `published_at`，重试或后续状态更新不改成功起点。文件名中的本地时间按 UTC+8 解析，包含 `blive_*_YYYY-MM-DD-HHMMSS` 格式。
- 手动保留：场次保留/取消保留持久化；保留取消尚未领取的回收任务，已领取任务执行前再次检查。回收页可查看全部源录播、手动保留场次和回收历史，普通读取不创建审核文件。
- 回收保护：排队和执行前检查当前源录制、转封装、分析、字幕、成片任务、上传/投稿与手动保留；录制状态不可确认时停止回收。沿用 Windows 回收站、根范围约束、冻结清单和逐项恢复机制。所有上传队列引用的成片、独立字幕、投稿资料和审核记录受保护。自动到期任务执行时重新检查开关和最新期限。
- 每日维护：正式 `\BiliveV2\BiliveV2Retention` 计划任务已注册，每日北京时间 03:00，无控制台启动，错过触发允许补运行，重复实例忽略。维护只在实际排出回收任务时唤醒 Worker，由既有任务执行链处理。

## 运行配置与边界

正式服务使用 `.secrets/runtime.toml`。升级时补入 `retention.enabled=false`，仓库模板同样关闭自动清理；期限默认仍为 5 天/24 小时。每日检查已安装，用户可在“设置 → 存储与清理”启用策略。这样不会因本次代码升级立即清理已有历史源文件。

实际网络投稿与真实生产文件进入回收站未作为本轮验收。封面投稿采用本地固定版本客户端的协议，外部成功/失败与重试行为通过注入客户端验证。计划任务注册、触发器和状态已读回，未来实际每日触发和重新登录尚未验证。截图的圆点和页签样式不在本轮范围。
