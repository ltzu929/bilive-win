# 第一版工作台 UI/UX 改造验收

日期：2026-10-04。基线：`develop` 从 `556639c` 快进到远端最新 `2749126`，依据 [设计草案](../design/Bilive_DESIGN_draft.md) 第 19–21 节完成第一版前端改造。

## 已实现

- 六页统一冷白背景、紧凑标题和控件、底线工作标签、文字与状态点，减少大型卡片和装饰性统计。
- 录播库采用 242px 场次辅助栏，可搜索、展开筛选和折叠；日期、主播优先，文件名为辅助信息。所选场次的实际时长、大小和片段数继续显示。
- 右侧采用共享播放器与常驻上下文，下方独立滚动，分为候选、字幕和成片三个模式。大画面、源视频/成片切换、范围编辑、人工补选、分析管理、证据分页和整场复核仍可访问。
- 保留决定通过新增 `/api/segments/{segment_id}/keep` 持久化，沿用版本校验、源/片段任务互斥、整场审核与批准保护。保留不修改媒体版本，不撤回有效成片或批准发布；判断失败的技术归因保留。保留或废弃成功后自动进入下一未审核候选，处理完后进入字幕模式。
- 字幕恢复为紧凑表格，正文占主要宽度；播放高亮对应行，行号定位，删除在悬停/聚焦时出现。不会自动抢夺编辑滚动位置。保存和识别沿用原有接口与草稿校验。
- 当前场次、片段和工作模式写入页面链接，刷新能回到相同编辑对象并恢复对应草稿。
- 成片模式集中编辑标题、简介和标签；生成、批准按钮常驻上下文。未保存草稿、失效成片及已批准锁定规则保留，“批准并发布”沿用现有 Worker 动作与人工授权。
- 直播间以在线和录制数量为简短摘要，手动录制控制保留在展开区。
- 发布队列当前任务优先显示失败和正在执行项，已发布进入历史标签；未批准成片仍可回到工作台确认，有远端媒体的失败项继续禁止重复上传。
- 主播页提供实际房间列表和最近 5 场录播回链，默认简介/标签保持可编辑；参数覆盖与人工指导放在高级展开区，已有建议/证据能力保留。
- 设置重组为自动化、字幕、发布、存储与清理、系统、高级六分区。现有自动切片和字幕外观支持跨区草稿、统一保存、放弃及离页提示；操作条只在修改后出现。两个接口顺序保存，部分失败如实显示已生效分区并保留失败草稿，可继续保存。
- 系统页正常状态简短呈现，服务控制在展开区；侧栏服务状态可跳转系统设置。

## 后续能力边界

第一版按文档 P0–P2 优先级完成前端结构与现有能力迁移；以下没有作为已实现能力展示：

- 高级参数和全局发布默认的网页写接口。
- 默认标题模板、默认分区的主播覆盖、默认封面生成/确认，以及最近发布快捷记录。
- 完整预览检查记录。
- 未处理 5 天、发布后 24 小时清理与手动保留。当前仍是实际后端的第 5 天提醒、第 7 天到期排回收及 Windows 回收站机制。

生命周期与发布规则没有因视觉改造替换。其他分辨率未作为精细验收结果。实际网络投稿、生产回收与真实 AI 分析不属于本轮验收。
