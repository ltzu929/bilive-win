# 项目说明

开发或排查时参考：产品约定、系统结构和实现边界。按 2026-10-10 整理，不表示运行中的服务已经重新验证。

## 工作台产品与设计约定

由原设计讨论草案整理，更新于 2026-10-10。本文保存产品目标与交互取舍，不作为全部像素、功能或真实服务都已验收的声明。当前能力和外部验证分别见 [实现边界](project.md#实现与验证边界)。

### 定位与视觉

Bilive 是 Windows 本地直播内容生产工作台，围绕录制、分析、审核、字幕、成片、人工批准和回收，让用户清楚当前对象、状态和下一项工作。

视觉以现有蓝白体系为基础：冷白、克制、桌面工具感，适中信息密度；浅冷灰背景与接近白色的核心工作区。蓝色主要用于主操作、选中、焦点与链接，B 站粉色只作少量品牌点缀。系统中文/UI 字体优先保证时间、文件名和字幕可读。

用细分隔线、背景差、对齐和间距建立层级，小到中等圆角，少阴影。避免通用 Dashboard 的大标题、装饰统计卡、渐变、高饱和状态块和“万物卡片化”。编辑器式底线 Tab、文字加小状态点优先，弹窗从严使用。精确尺寸允许按真实窗口调整，不为像素规范牺牲工作空间。

### 共通交互

- 当前有一个突出的主操作，其他操作可达；允许返回修改，不强制线性向导。
- 播放器和高频上下文常驻，长列表独立滚动；低频控制折叠或按需显示。
- 字幕正文直接编辑，时间与破坏性操作次要；不预先堆叠批量工具。
- 连续审核完成一项后进入下一项未处理；AI 展示简短依据，不以置信度分数主导人工决定。
- 完整预览记录辅助批准，不强制完整播放；发布资料在成片阶段确认，队列负责执行与异常。
- 加载保持布局，长任务显示真实阶段；重要错误原位持续显示并给出下一步，不只依赖 Toast。
- 未保存草稿、版本冲突、活跃任务、批准锁定和错误状态不能因视觉改造移除。

### 六页面职责

| 页面 | 职责与结构 |
|---|---|
| 录播库 | 核心工作台：窄录播选择栏、共享播放器/上下文、下部候选/字幕/成片模式；选中后选择栏可折叠 |
| 直播间 | 自动录制状态面板；紧凑摘要和房间条目，异常优先，不加入直播观看区 |
| 发布队列 | 正在执行、失败和需要处理的任务优先，成功进入历史；不重复编辑投稿资料 |
| 主播档案 | 主播长期默认与最近记录跳转，避免成为第二个录播库 |
| 录播回收 | 生命周期、即将到期、回收结果和手动保留；不建立长期占空间的软件回收站 |
| 设置 | 按自动化、字幕、发布、存储与清理、系统、高级组织；分区修改、统一保存 |

### 录播与编辑细节

录播优先显示主播、日期/时间、时长、状态与剩余工作，按时间倒序；文件名次要，筛选不占据主区域。选择栏建议 220–260px，上部上下文区建议 280–320px，可按窗口与真实内容调整。

候选只展示范围、时长、建议和简短原因，选中跳到对应时间；保留/废弃后连续推进。详细弹幕与技术证据按需展开。字幕以紧凑列表呈现，正文占主要宽度；点击行定位播放，编辑时不抢夺滚动，删除/拆分等低频行操作按上下文显示。

成片模式聚焦预览、版本、生成状态、标题/简介/TAG/分区与默认封面；生成后人工批准直接进入发布队列。范围/字幕变化明确显示失效并要求重新生成。封面采用系统默认生成，不把手动选帧/上传做成主流程。

### 默认值与设置

发布配置继承“全局 → 主播 → 单片段”，单次修改不反写默认。主播页保留少量最近录播/发布入口；不为了未来扩展预先增加独立 AI 规则或自动发布复杂度。现有主播指导和审核经验仍保留。

字幕页负责普通外观与预览；模型、设备、VAD、并发等进入高级。使用人话标签，内部字段名只作辅助。统一保存说明未保存项、非法值与生效方式；需要重启时明确提示。正常服务状态弱化，异常时可跳转排查。

源录播是临时素材；当前 5 天/24 小时策略、关闭模板开关及活跃/手动保留保护以 [维护说明](../usage/README.md#维护与开发验证) 为准。用户的长期自动化目标不自动意味着无人审核发布。

## 系统架构与状态约束

按 2026-10-10 仓库代码整理。项目为 Windows 单机工作台，不引入旧 Pi/SMB/SSH 部署；复用来源和许可证见 [PROVENANCE](../../src/bilive/vendor/PROVENANCE.md)。

### 进程与模块

| 组件 | 职责 | 入口/模块 |
|---|---|---|
| blrec / 2233 | 直播录制、弹幕、同源工作台代理与完成事件 | `start_windows_recorder.ps1`、`src/bilive/recorder/server.py` |
| Dashboard / 2234 | 查询、验证、草稿、配置与持久任务提交 | `scripts/start_dashboard.py`、`src/bilive/api/` |
| Worker / 本机 2235 | 预检、领取和恢复任务，分析、成片、回收 | `scripts/start_worker.py`、`src/bilive/worker/` |
| 上传消费者 | 消费已授权 SQLite 队列、上传与投稿 | `scripts/start_upload_consumer.py`、`src/bilive/upload/` |
| 浏览器前端 | 六页面与编辑草稿 | `frontend/` 原生 JavaScript/CSS，无 Angular 构建链 |

Dashboard 不在请求中执行模型、转码等重处理；只读接口不唤醒 Worker、不隐式创建上传库。任务先落盘再请求唤醒，启动失败任务仍保留。

### 数据与时间

源录播、候选、人工片段、成片、字幕、分析记录、审核、动作任务和上传行分别保存。主要目录为 `Videos`、`artifacts`、`.bilive-jobs`、`.runtime`，上传事实保存在 SQLite。凭据与机器路径不提交。

| 时间 | 坐标 |
|---|---|
| 源区间、核心区间 | 源录播绝对秒 |
| MiMo trim、辅助 ASR 提示 | 候选相对秒 |
| 编辑与烧录字幕 | 最终片段相对秒 |

源/片段/媒体标识限制在配置根内。片段范围修改保留身份但增加版本；旧成片引用失效，残留媒体不能恢复有效状态。

### 流水线与状态

录制完成 → 验证转封装 → 手动或配置开启的分析 → 弹幕召回 → 可选辅助 ASR → MiMo → 质量门/去重 → 正式字幕 → 裁剪烧录 → staged → 人工批准 → 上传/投稿 → 终审与生命周期回收。

| 对象 | 状态 |
|---|---|
| 录像/动作任务 | `pending → processing → done / failed` |
| 判断 | `keep / manual_keep / review / judge_failed / drop` |
| 上传 | `staged → queued → uploading → uploaded → publishing → published`，另有 `failed / cancelled` |
| 审核 | `unprocessed / processing / source_review / candidate_review / review_complete / trash_pending` |
| 回收 | `pending / processing / done / failed / blocked` |

动作任务通过跨进程锁与 owner 租约互斥，坏任务隔离，孤儿任务按既有机制恢复。提交/领取前检查片段版本、活跃任务和发布保护；不承诺任意手改 JSON 或任意跨文件中断均有事务恢复。

只有明确 drop 可自动删候选。质量门、重复、字幕失败保留人工可复核依据；共享候选存在保留结果时不整删。模型空结果不能冒充整场无内容确认。

正式字幕使用有界 padding、有效辅助识别复用与句边界吸附；当前聊天边界保护向外选择容差内最近边界。对齐后新增重复保留字幕但不渲染。校正不得改时间或行数。

### 发布与回收保护

生成只暂存，人工批准才激活。上传后失败的投稿复用远端媒体；手动重新上传限 failed 且无远端标识。消费者默认自制投稿；认证不足不领取。停止等待当前操作结束，不把清理失败当成重新投稿理由。

手动终审与自动到期回收是不同入口。两者都检查活跃任务、根范围、源包与受保护媒体，记录独立审核/回收结果；正常查询不创建审核文件。生命周期默认值及开关位置见 [维护说明](../usage/README.md#维护与开发验证)。

### 仍需单独验证

- 外部模型更新后的实际视频判断/校正效果。2026-10-10 已更新到 `mimo-v2.6-flash`；64 项定向测试首轮 63 通过、1 项 Windows 文件替换权限失败，该项单独重跑通过，没有真实付费模型调用。
