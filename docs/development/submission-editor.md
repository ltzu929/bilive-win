# 视频投稿页

投稿页作为“发布队列”下的二级页面，沿用项目字体、颜色与导航；按 B 站投稿习惯组织视频文件、基本信息、更多设置与底部提交操作。

## 入口与流程

- 录播库 → 选择切片 → 成片 → **去投稿**。
- 发布队列 → 选择待确认切片 → **编辑投稿**。
- 页面地址：`#/submission?segment_id=<片段 ID>`；侧栏选中“发布队列”。
- **保存草稿**仅保存资料，队列保持 `staged`；**提交投稿**先保存当前修改，再创建 `approve_publish` 任务，处理完成后定位发布队列中的对应切片。
- 返回成片检查会打开原录播、原切片及成片标签；进入投稿页本身不会批准发布。

支持标题、简介、标签、数字分区、话题/活动、合集/小节、粉丝动态、当前封面与成片预览，以及按已保存字幕生成并明确采用文案建议。粉丝动态最多 233 字，贯通片段快照、暂存队列、重烧和投稿重试。省略动态字段保留已有值，空字符串明确清空。

封面目前使用已生成成片的默认封面；分区仍填写编号。自选封面、定时发布、创作声明、可见范围与评论/弹幕等账号能力选项尚未接入，调查依据见 [B 站投稿页 REA 记录](bilibili-submission-rea-20261017.md)。

## 草稿与状态保护

浏览器本地草稿按录播与切片隔离，兼容原工作台的文案草稿。保存失败保留填写内容；版本变化时先核对当前成片，再明确选择继续编辑，重新保存页面显示的全部资料。提交中的任务禁止重复创建，已批准或已废弃切片锁定编辑。无有效成片时允许先保存资料，禁止提交投稿。

若新前端连接到仍未重启的旧后端，动态文案回读不一致会保留草稿并阻止继续提交，避免静默丢失。

## 运行进程

本次实现未重启现有 Dashboard、Worker 或上传进程，未改动真实发布队列。前端静态资源已能通过 `/workbench/assets/submission.js` 读取；运行中的旧 API 尚无 `dynamic` 字段。完整启用新字段需要在现有后台与上传任务结束后重启 Dashboard 和 Worker，使上传子进程也加载新版本。源码与隔离测试通过不代表运行进程已经更新。
