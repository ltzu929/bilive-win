### 聊天切片的优先改进方向（2026-10-11 用户确认）

先改善单条切片的有效内容密度，再扩大产量。主要针对聊天、整活和弹幕互动；唱歌不作为专项。以下是已确认的改进方向，尚未实施或完成效果验证。

1. **事件结束就收尾，优先验证。** “帮狐狐找老婆”保存的字幕约在第 33 秒结束标题对应观点，片段却长约 111 秒，后续主要为谢舰长、报页数和告别；“按摩办卡”也夹入较长谢礼。两条媒体已不在原路径，当前依据是字幕和分析记录，不能据此确认视听效果或低播放原因。选段应明确指出标题事件的最后一个有效回应，以此确定结束位置；谢礼本身构成梗时保留，不按关键词机械删除。此前一次提示调整验证仍有拖尾，不能将补充提示当作问题已解决。
2. **开头让陌生观众能理解。** 新合同片段以“是有来跟我们说过的”开头，随后进入官签与合同流程，是否缺少必要前情仍需试听。检查人物、事情和必要背景能否在短开头交代清楚；不一律延长铺垫，不为了句子完整引入无关对白。
3. **标题、简介以最终成片为依据。** 合同片段标题中的“两年半”在保存的选段字幕中未找到支持，可能指签约资历而非等待时长；简介里的“光头是我妈”也未出现在现有字幕中。成片尾部仍有未独立核实的内容，因此这些是待核对线索，不能直接判错。选段完成后逐条核对标题事实和简介承诺的梗，定位到最终成片的具体秒数，避免沿用整个候选窗口的描述。

### 1. 模型的思考强度

比较关闭与开启思考对选段完整性、拖尾、误判、结构化输出的影响，同时记录延迟、tokens 与费用。开启思考时需要重新评估当前 2048 tokens 的预算。

先核对接口实际支持的控制粒度。Chat Completions 提供 `thinking.type` 开关；Responses 文档说明 `reasoning.effort=none` 关闭思考，其他档位目前均开启思考且行为相同，尚不区分强度。未来若支持独立强度档位再评估接入，不能把档位名称当成已生效的能力。

参考：[Chat Completions](https://mimo.mi.com/docs/zh-CN/api/chat/openai-api)、[Responses](https://mimo.mi.com/docs/zh-CN/api/chat/responses)。

### 2. 使用 MiMo ASR

评估 `mimo-v2.5-asr` 对直播口语、专名、方言、背景音乐和多人说话的识别效果，与现有 large-v3 使用同一批人工核对样本比较。重点确认字幕需要的时间戳粒度与精度、长音频限制、上传耗时及费用，验证能接入现有时间对齐与人工编辑流程，再决定替换或作为可选入口。

ASR 是独立模型，不能因语言模型升级而推断其名称也升级。官方当前列出 `mimo-v2.5-asr`，国内价格为 0.5 元/小时；实施前重新核对接口与价格。

参考：[定价](https://mimo.mi.com/docs/zh-CN/price/pay-as-you-go)。

### 3. 优化提示词

### 4. 使用批量推理并比较 Flash 与 Pro

状态：2026-10-12 经用户确认记录；2026-10-13 开始视频 Batch 可行性验证，文件上传未通过，用户随后要求暂停，尚未创建推理任务或开展质量对照。目标是降低选段实验费用，并判断 Pro 是否能改善缺少开头铺垫、结尾缺少后续回应、只截取话题中间一部分等问题；不预设 Pro 必然更适合本项目。

适用场景：周复盘、同一批素材的选段提示对比、可等待结果的录播分析及积压任务。手动即时重判、文案建议和字幕编辑需考虑交互等待成本，保留实时调用的选择。批量推理与实时请求并发设置是不同机制。

2026-10-12 核对的官方国内价格如下，单位为元/百万 tokens，输入列为未命中缓存价格；实施前重新核对价格与调度规则。

| 调用方式 | 输入（未命中缓存） | 输出 |
| --- | ---: | ---: |
| Flash 实时 | 1.00 | 2.00 |

视频可行性：官方视频文档列出 Flash 和 Pro 均支持 URL/Base64；Batch 文档要求请求 body 沿用模型接口格式。结合两项规则，视频请求应可用于 Batch，这是文档推断，尚无本项目视频 Batch 的端到端验证。现有 Base64 视频输入是待验证的复用方式；单视频 Base64 默认上限 50 MB，Batch JSONL 文件默认上限 128 MB，需要按实际编码大小分组。

1. 用同一段视频分别提交一次 Flash 和 Pro Batch，确认视频可读、任务结果可下载、返回范围合法，并记录实际完成时间和用量。

3. 做 Flash/Pro × 现有提示/强调完整事件的新提示四组对照。各组使用相同视频、采样参数及思考模式，输出预算足以完成结构化结果；保存提示版本、原始响应和实际用量，避免将模型与提示的效果混为一谈。
4. 隐藏模型名称后对照音画评价：能否独立理解、事件覆盖是否完整、切点是否自然、是否混入无关内容、漏选/误删及人工修改量。模型自评或片段变长不能替代观看评价；同时比较失败、耗时和真实费用。

按实验结果决定保留 Flash、仅将复杂互动与难例交给 Pro，或扩大 Pro 使用；生产接入另行确定。接入时核验请求与候选的关联、提交/结果状态、失败和取消行为、结果落库及人工审核。当前未提交付费 Batch 任务，也未启用 Pro 或修改生产选段策略。

参考：[Batch API](https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/text-generation/batch-api)、[视频理解](https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/multimodal-understanding/video-understanding)。

使用同一组代表性素材和人工核对标准，记录质量、耗时与费用；区分模拟回归和真实模型效果。2026-10-13 用户已要求暂停隔离实验，后续需用户恢复后再继续；生产接入另行确定。
