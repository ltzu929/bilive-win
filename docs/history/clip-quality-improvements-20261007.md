# 真实切片问题与本轮改进

> 历史记录：仅说明文中日期与验证范围，旧运行快照和阶段待办不代表当前状态。当前说明见 [文档导航](../README.md)。

日期：2026-10-07。诊断来自现有片段、字幕、分析记录与一次获用户明确授权的真实 MiMo 候选重评；本轮未独立试听或观看成片，不把字幕观察当作全部视听证据。

## 已查实的问题

1. 人工 `transcribe_subtitles` 只返回原始 ASR 草稿，没有使用自动分析流水线已有的轻量文字校正。已有人工字幕出现“上剑”“上件”等疑似听错，需结合音频核对；代码路径缺口已确认。
2. 模型有将“直播自然收尾”当作“标题事件完整收尾”的倾向。现有 111 秒的“帮狐狐找老婆”片段，其字幕在约 33.34 秒已结束标题对应的观点，之后包含谢舰长、礼物页数和长段告别。不能仅凭这个观察断言播放低的原因。
3. 另一条唱歌片段中，“好开心啊终于有人要听歌了”一行字幕从 6.80 秒延续到 39.37 秒，并与下一行有少量重叠。存在字幕显示过长的检查线索，需试听确认实际话音边界；本轮不按任意时长上限裁剪字幕。

## 本轮实现

- 人工识别按现有 `subtitle.light_correct` 配置使用轻量校正，使用主播和片段标题作为上下文。自动、人工路径共用文字校正的时间与行数检查。
- 只允许改字幕文字，不允许改时间、增删行或置空。校正错误或输出不符合约束时保留原始草稿。结果仍需人工核对保存，不写旧字幕、成片或发布许可。
- 草稿结果带校正状态与修改行数，区分关闭、已修改、未修改和拒绝后保留原文；“未修改”不声称模型成功完成过校正。
- 选段提示新增主题约束：完整性属于一个标题事件；无关的例行谢礼、页数汇报、告别和转场不为该事件补足完整性。谢礼、抽奖或告别本身是梗时保留必要部分，不按关键词删除，不强行限制片长。

- 覆盖文字校正、时间不变、草稿未保存时旧媒体与队列保留，以及校正改时间、空文字、删行、服务异常时保留原文。现有自动校正、ASR 对齐、重复检测、MiMo 解析回归通过。
- Git 差异格式检查通过。没有执行真实字幕校正调用；字幕改进的服务集成以模拟校正结果验证。

## 后续本地验证与修复

- ASR 启用 faster-whisper 原生 `word_timestamps`，保留词级时间信息，句子时间由识别器对齐；不按固定最长秒数截字幕。
- 对同一唱歌片段原有完整 `asr_window.mp4`（144 秒）执行本地 large-v3 / CUDA / float16 / batch 8 识别，没有调用外部模型。该窗口起点 3103 秒，成片起点 3108.86 秒。
- “好开心啊终于有人要听歌了”新时间为窗口相对 12.32–14.84 秒，换算成片相对 6.46–8.98 秒，持续 2.52 秒；旧字幕为 6.80–39.37 秒，持续 32.57 秒。新结果不再与下一句歌词重叠。记录在 `artifacts/research/quality-review-20261007/singing-word-alignment.json`。
- 此证据来自识别器对齐，未独立试听证明每个词均正确。歌词与谢礼仍有错字；词级对齐不能代替人工核对，也不能证明所有唱歌样本都能稳定识别。
- 辅助 ASR 给选段模型的内容改为逐句候选相对时间，以便对照主题落点与后续谢礼。长度预算只保留完整行，避免截断句子或时间标签。本次没有再次调用外部 MiMo；主题收尾改善仍待更多样本验证。
- 后续相关回归合计 111 passed：ASR 适配器、分析流水线、MiMo 解析 51 项；空字幕与人工工作台 60 项。后一组在受限环境停滞后中断，改在主机隔离临时目录重跑全部通过（70.77 秒）；不将被中断的一次算作通过。编译与差异格式检查通过。
